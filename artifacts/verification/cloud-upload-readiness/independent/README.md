The final guard holds unseen, changed, unreadable or conflicting cloud work. Absent rows use represented INSERT rather than upsert; existing rows require exact acknowledged version and canonical JSON fingerprint and use conditional UPDATE. Fresh or old display timestamps never establish permission. Account/project/client revision, exact local bytes, import token and current acknowledgment owner are guarded across reads and hashes; accepted restore checks again inside the data write lock. Returned upload contents are validated against the sent payload before acknowledgment. Existing raw fetched legacy data is fingerprinted before normalization. Cancelling or previewing a restore does not acknowledge it.

Important bounds: a legacy writer changing contents while retaining `updated_at` **between SELECT and conditional UPDATE** can still be overwritten; the final harness reproduces this explicitly. Timestamp CAS and pre-read fingerprints are not a complete conflict protocol. A strict fix for that remaining race requires separately approved server-atomic comparison. This synthetic review does not validate deployed schema/RLS, real OTP, a simulator or physical native devices. The one shared device dataset and whole-document replacement policy remain; there is no automatic winner, merge or new per-account local storage. Publication remains subject to the parent's review checkpoint.
