# Independent integration review · 30 September 2026

Reviewed the shared implementation from a returning member's perspective: onboarding interruption, native dialog behavior, Today planning, daily/weekly reflection, applied course work, local restore, optional cloud sync, and the interaction between course and notebook persistence. No production data, credentials, paid services, deployment or push were used.

## Findings and disposition

| Finding | Evidence and consequence | Disposition |
| --- | --- | --- |
| First planning offer was consumed before its delayed opening | `Today` wrote the seen marker before a 700 ms timeout. React StrictMode replay or quick navigation could cancel that timeout after the marker was saved. The candidate could also differ from the decision passed into the modal. | Corrected in the current source: use the selected daily decision; write the marker when the offer opens. Root reports keyboard browser verification. |
| Course writes did not share the repository write lock | Course progress wrote the whole personal JSON record outside the repository's `oda-data-writes` lock. Sequential stale-save protection alone cannot prevent cross-tab read/write interleaving. | Corrected in the inspected source: repository and course writes now use `dataWrites.ts`, course mutations re-read under the same lock, and queued updater drafts survive failed saves. The persistence owner's lock-interleaving regression passes in a targeted rerun; final combined-suite execution remains with the root agent. |
| Malformed optional backup records passed validation | Isolated Chromium contexts reproduced accepted corrupt records: `lifeScores: [{}, {}]` breaks Me's timestamp sorting; `realityBridges: [{}]` breaks numeric formatting; a pinned custom dream with an object-valued name breaks Today's React rendering. Object-valued weekly-review text also passed the old validator and is rendered directly. A confirmed restore could replace usable data with these records. | Corrected by strengthened optional record validation. All four independent `tests/backup-rendering-safety.test.ts` regressions pass against the patched validator, including checks that rejection leaves the original saved JSON unchanged. |

The malformed-record reproductions started from the app's own initial data and altered only the named fields. Browser fixtures were confined to fresh contexts. The pre-fix browser result is preserved at `artifacts/native-readiness/backup-validation-before-fix.json`. `purchases: [{}]` did not crash the default Dreams view in that check, so no immediate-crash claim is made for that case.

## Working safeguards

The inspected implementation retains unsaved course state and offers retry when persistence fails; daily and weekly drafts stay separate from submitted records; backup previews explain replacement and provide a download action; local-restore markers prevent a later cloud pull from silently reversing an explicit import. Native notification previews have independent IDs, replacement scheduling is serialized, and foreground refresh rechecks permissions.

The earlier native/support checks remain limited to web/static behavior and the iOS-target web bundle. Xcode, real iPhone lifecycle and delivery, VoiceOver, StoreKit/RevenueCat and configured Supabase behavior require their respective environments. This review does not certify App Store acceptance or personal-growth outcomes.
